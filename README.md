## 🎯 The Problem

Today, AI is everywhere — trading bots, risk engines, sentiment analyzers, oracle networks. But there's a fundamental trust gap:

| Problem | Impact |
|---------|--------|
| **Black-box AI** | Users can't verify if a model actually ran correctly |
| **Centralized inference** | One party controls the model, the data, and the output |
| **No accountability** | If an AI agent makes a bad decision, there's no on-chain proof of what happened |
| **Fake results** | Anyone can claim "the AI said X" without evidence |
| **No reputation** | Good agents can't prove their track record, bad agents can't be penalized |

> **In short:** How do you trust an AI's output without re-running the entire computation yourself?

---

## 💡 The Solution

**ChainMind** solves this by combining three paradigms:

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   Decentralized AI         Zero-Knowledge ML          On-Chain  │
│   Agent Registry    +      Proof Generation     +     Verification │
│                                                                 │
│   Agents register          Every inference              Proofs are    │
│   with staked tokens,      generates a ZK              verified by    │
│   ONNX models, and         proof that the              smart contract │
│   verification keys        computation was             — trustlessly  │
│                             done correctly                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**The result?** Anyone can verify that an AI model produced a specific output for a specific input — without seeing the model weights, without re-running the computation, and without trusting the operator.

## 🌍 Why This Matters in the Real World

### 1. DeFi & Autonomous Trading

### 2. Insurance & Risk Assessment
Decentralized insurance protocols need AI risk scoring. ChainMind ensures the risk model ran correctly on the actual data — not a manipulated version that benefits the insurer.

### 3. Decentralized Oracle Networks
Oracles feed data to smart contracts. An AI-powered oracle using ChainMind can prove its predictions were generated by a specific model architecture, not fabricated.

### 5. Healthcare & Legal AI
In regulated industries, you need audit trails. ChainMind creates an immutable, verifiable record that a specific model produced a specific output — critical for compliance.

## ⚙️ How It Works

```
User submits task          Agent picks it up          Proof goes on-chain
       │                         │                          │
       ▼                         ▼                          ▼
┌──────────────┐  ┌─────────────────────────┐  ┌──────────────────────┐
│              │  │  1. Load ONNX model     │  │                      │
│  Task        │  │  2. Run inference       │  │  ProofVerifier.sol   │
│  Marketplace │──│  3. Generate witness    │──│  verifies the ZK     │
│  (on-chain)  │  │  4. Create ZK proof     │  │  proof on-chain      │
│              │  │  5. Submit proof + tx   │  │                      │
└──────────────┘  └─────────────────────────┘  └──────────────────────┘
       │                                                │
       ▼                                                ▼
  CMT tokens                                    Reputation score
  staked as bond                                updated on-chain
```

### Step-by-Step Flow

1. **Agent Registration** — An AI operator registers their agent on-chain by staking CMT tokens and providing the IPFS hash of their ONNX model and verification key.

2. **Task Creation** — A user creates a task on the TaskMarketplace smart contract, specifying what type of inference they need (sentiment analysis, price prediction, risk scoring).

3. **Agent Claims Task** — A registered agent claims the task. The agent's stake acts as a bond — if they produce invalid results, they lose their stake.

4. **Inference Execution** — The agent's AI engine loads the ONNX model, runs the forward pass on the input data, and records the computation trace.

5. **ZK Proof Generation** — Using the EZKL framework (Halo2 backend with KZG commitments), the agent generates a Zero-Knowledge proof that:
   - The correct model was used (matching the registered model hash)
   - The computation was performed correctly (no tampering)
   - The output matches the claimed result

6. **On-Chain Verification** — The `ProofVerifier.sol` smart contract verifies the proof on-chain. No one needs to trust the agent — the math proves correctness.

7. **Reputation & Rewards** — Successful verifications increase the agent's reputation score (soulbound, non-transferable) and release CMT token rewards. Failed proofs trigger stake slashing.

## 🚀 Quick Start

### Prerequisites
- **Node.js** 18+ ([download](https://nodejs.org/))
- **Python** 3.11+ ([download](https://python.org/))
- **Git** ([download](https://git-scm.com/))

### Installation

```bash
# Clone
git clone https://github.com/PNMS2026/chainmind.git
cd chainmind

# Smart contracts
cd contracts && npm install

# Backend API
cd ../backend && npm install

# AI engine
cd ../ai-engine && python -m venv .venv
# Windows:
.venv\Scripts\pip install -r requirements.txt
# macOS/Linux:
# .venv/bin/pip install -r requirements.txt

# Frontend
cd ../frontend && npm install
```

### Run Locally

```bash
# Terminal 1 — Local blockchain
cd contracts && npx hardhat node

# Terminal 2 — Deploy contracts
cd contracts && npx hardhat run scripts/deploy.js --network localhost

# Terminal 3 — AI engine (port 8000)
cd ai-engine && .venv\Scripts\python src/api_server.py

# Terminal 4 — Backend API (port 3001)
cd backend && node src/index.js

# Terminal 5 — Frontend (port 3000)
cd frontend && npm run dev
```

### Docker (One Command)

```bash
docker-compose up
```
